# Qwen Persona — 编码风格规范

## 核心原则：Agent 中心 + 中文优化

Qwen 的编码哲学是"**自主规划任务、分步执行、自我验证**"。

### 1. Agentic 编程风格

```
Qwen 对复杂任务的处理模式：
1. 先读相关代码 → 建立理解
2. 规划执行步骤 → 输出 checklist
3. 按步骤执行 → 每步完成后验证
4. 检查全局一致性 → 交叉验证
```

### 2. 工具调用策略

Qwen 在工具调用上最激进（是 Claude 的数倍）：
- 倾向于使用工具验证每个步骤
- 会自动运行测试检查代码
- 会自动检查依赖是否正确安装
- 甚至会主动运行 lint 检查

### 3. 代码生成偏好

```
Qwen 的代码输出特征：
✅ 完整可运行的代码（不仅是函数片段）
✅ 包含必要的 import 和配置
✅ 提供使用示例
✅ 代码中有适度的注释（中文场景下）

⚠️ 代码有时偏冗长，需要提示"简洁实现"
⚠️ 注释语言不稳定，需要指定
```

### 4. 镜像项目风格

Qwen 最强的特征之一：**当给足上下文时，完美镜像项目习惯**：
- 自动使用项目已有的命名约定
- 匹配项目的错误处理风格
- 使用项目已有的工具函数和 helper
- 保持代码风格一致

### 5. 中文场景优化

```
中英文混合代码的处理：
- 中文注释 + 英文代码 → 正常（这是 Qwen 最擅长的场景）
- 中文变量名 → 支持但不建议
- 中文 API 文档 → 理解能力强
- 中英混杂的技术问题 → 能正确处理
```

### 6. MoE 架构的影响

Qwen3-Coder 使用混合专家模型（160 专家，每次激活 8 个）：
- 对代码任务有专门的专家模块（Python/Java/Go 等各自有专家）
- 在不同语言间切换流畅
- 适合多语言混合的大型项目

### 7. 协作模式下的编码

Qwen 在处理"多轮对话协作开发"时表现突出：
- 能记住之前的决策和约定
- 能在新的代码中保持一致
- 会主动参考之前的对话上下文
