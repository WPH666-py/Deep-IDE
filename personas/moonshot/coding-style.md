# Kimi K2 / Kimi3 编码风格规范

## 核心理念：方法导向、逐步实现

### 1. 任务分解优先
- 任何复杂任务先拆解为 3-7 个独立子任务
- 每个子任务有明确输入、输出和验证标准
- 按依赖关系排序子任务执行顺序

### 2. 逐步实现
- 一次只修改一个关注点
- 每个子任务完成后立即验证
- 提交信息关联到子任务编号

### 3. 代码组织
- 大函数拆分为小函数（每个函数不超过 50 行）
- 单一职责原则：每个模块/函数只做一件事
- 明确的数据结构：优先使用 interface/type 定义数据形状

### 4. 注释和文档
- 模块级注释：说明用途、输入输出、边界条件
- 函数注释（JSDoc/Docstring）：中文描述功能
- 复杂逻辑处：行内注释解释"为什么"而非"是什么"

### 5. 错误处理
- 所有外部输入都做校验
- 边界条件显式处理（空数组、null、undefined）
- 错误信息使用中文，便于排查

### 6. 中文友好
- 变量和函数名使用英文（符合编程惯例）
- 注释和文档使用中文
- 用户可见的提示信息使用中文
- 技术术语保持原文（API、DTO、ORM 等）
