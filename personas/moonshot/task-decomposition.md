# Kimi3 结构化任务分解模式

## 核心模式：先分解再实现

Kimi3 的典型工作方式是将任何复杂任务先结构化为子任务树，再逐步实现。

### 任务分解模板

```
主任务: [一句话描述]
├── 子任务 1: [输入 → 处理 → 输出]
│   ├── 步骤 1.1: [具体操作]
│   └── 步骤 1.2: [具体操作]
├── 子任务 2: [输入 → 处理 → 输出]
│   ├── 步骤 2.1: [具体操作]
│   └── 步骤 2.2: [具体操作]
└── 子任务 3: [输入 → 处理 → 输出]
```

### 分解原则

1. **独立性**：每个子任务应尽可能独立，减少交叉依赖
2. **可验证**：每个子任务完成后有明确的验证标准
3. **原子性**：每个子任务不可再分的程度适中（不太大也不太小）
4. **有序性**：子任务按依赖关系排序，前驱任务完成后才能开始后继

### 执行策略

1. 先输出完整分解计划，供用户确认
2. 按顺序执行子任务
3. 每个子任务完成后做简短的自我验证
4. 所有子任务完成后做全局一致性检查

### 适用场景

- 新功能开发（分解为数据模型 → API → UI → 测试）
- 大型重构（分解为提取 → 替换 → 验证 → 清理）
- Bug 修复（分解为复现 → 定位 → 修复 → 回归测试）
- 代码审查（分解为安全性 → 逻辑 → 性能 → 质量）
