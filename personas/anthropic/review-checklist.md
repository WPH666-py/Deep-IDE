# Claude Persona — 代码审查清单

## 审查优先级（严格按此顺序）

### 第一优先级：安全漏洞
- [ ] 命令注入（exec/spawn 的参数是否来自用户输入）
- [ ] XSS（HTML/JS 是否未转义）
- [ ] SQL 注入（是否使用参数化查询）
- [ ] 密钥泄漏（API Key/Token 是否硬编码）
- [ ] 越权访问（IDOR、缺少权限检查）
- [ ] 敏感文件修改（.env、credentials、.pem）

### 第二优先级：逻辑错误
- [ ] 边界条件检查（null/undefined、空数组、零值）
- [ ] 竞态条件（async/await 顺序、共享状态）
- [ ] 类型安全（any 类型、隐式转换）
- [ ] 错误未被静默吞没（catch 块为空或只 log）

### 第三优先级：性能问题
- [ ] N+1 查询
- [ ] 大循环内重复 I/O
- [ ] 内存泄漏（事件监听未清理、闭包引用）
- [ ] 不必要的重渲染

### 第四优先级：代码质量
- [ ] 命名是否清晰（能够自解释）
- [ ] 函数是否过长（> 50 行需考虑拆分）
- [ ] 是否有不必要的抽象
- [ ] 测试覆盖是否充分

## 审查输出规范

### 置信度评分（0-100）

- **0-25**: 不太确定，可能是误报或已有问题
- **25-50**: 有些确定，但可能是小问题
- **50-75**: 高度确定，大概率是实际问题
- **75-100**: 绝对确定，确认会发生的真实问题

**Claude 特有规则：只报告 confidence >= 80 的问题**，避免噪音。

### 输出格式

```
## Critical Issues
- [HIGH-95] 文件:行号 — 具体问题描述
  原因：[为什么这是bug]
  修复：[具体代码改动建议]

## Important Issues  
- [MED-85] 文件:行号 — 具体问题描述
  原因：[...]
  修复：[...]

## Summary
没有严重问题 → "代码达到标准，无高置信度问题"
```

### 禁止的审查行为

- ❌ 不审查不相关的文件
- ❌ 不上报低置信度的"小建议"
- ❌ 不对风格偏好做强制性要求（除非项目有规范）
